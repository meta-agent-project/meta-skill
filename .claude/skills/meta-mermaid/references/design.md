# meta-mermaid 디자인 결정 기록

2026-10-08 사용자와 정했다(웹 원고 · 교재용 도식).
2026-10-09 흐름 도식 직각 배치를 더했다.
2026-10-10 harness 저장소의 codelab-mermaid를 전역 스킬 meta-mermaid로 옮겼다.

## 출발점

사용자 요청은 "기본 머메이드 디자인이 마음에 안 든다. mono에 검정 글자, 하얀 바탕 형태로 모던한 느낌."이었다.
샘플로 흰 바탕 · 검은 선 · 회색 머리 칸 · 까마귀발 관계선의 ER 그림을 줬다.

## 시안 3개

| 시안 | 방향 |
|---|---|
| A 도면형 | 샘플 그대로. 흰 상자 · 검은 1.5px 선 · 머리 칸 옅은 회색 · 각진 모서리 |
| B 선만 | 채움 없음 · 검은 1px 선 · 작은 둥근 모서리. 가장 가벼움 |
| C 반전 머리 | 머리 · 노드 검정 채움 + 흰 글자(반전 라벨 알약 결) · 1px · 둥근 모서리 |

사용자는 B를 골랐다.

## B를 고친 세 번

- 첫째. "제목 글자는 진하게, 중요한 글자는 진하게" → ER 엔티티 이름 · 순서도 참여자 · 묶음 제목 굵게, ER PK 줄 굵게, 라벨 안 굵게 표시 굵게.
  "ER은 위에서 밑으로 내려가 스크롤해야 한다. 가로 배치가 되는 것은 가로로, 관계선이 겹치지 않게" → ER · 상태도는 방향이 없으면 direction LR. dagre와 ELK를 비교했고 dagre가 선이 덜 겹치고 상자에 덜 붙어 dagre를 쓴다.
- 둘째. "가로 스크롤은 안 돼, 나중에 책에도 넣어야 하니까. 가로 안에 다 못 넣으면 도형을 각각 줄여 가로로 두고, 너무 작아지면 세로로" → 폭을 넘으면 간격 · 여백을 좁혀 다시 그리고(ER은 nodeSpacing · rankSpacing 30, entityPadding 8, minEntityWidth 60) 폭에 맞게 줄인다. 줄인 글자가 11px보다 작아지면 세로.
  샘플 ER(엔티티 6개)은 원래 1086px → 좁히면 936px → 760 폭에서 81%, 글자 11.4px로 한 화면에 가로.
- 셋째. "넓은 흐름도 가로로 가다가 밑으로 가다가 할 수 없어? 세로로만 있어서 오른쪽 여백이 남는다" → 갈래 없는 한 줄 흐름은 줄바꿈 배치.
  mermaid에는 줄바꿈 배치가 없고, 묶음(subgraph) 안 노드가 밖과 이어지면 묶음 방향이 무시된다.
  그래서 줄마다 subgraph + direction LR로 다시 쓰고, 줄 사이는 보이지 않는 연결(~~~)로 자리만 잡고, 꺾인 연결선은 그린 뒤 SVG에 직접 더한다.

폭에 대해 "원래 이렇게 좌우를 남겨야 하나?"라는 질문이 있었다.
760은 읽는 글 폭(한 줄 길이를 읽기 좋게 제한하는 값)이라고 설명했다.
사용자는 도식도 글 폭에 맞춤(도식만 넓히지 않음)을 골랐다.
책과 같은 모양이 나오게 하기 위해서다.

## 2026-10-09 흐름 도식 직각 배치

- 흐름 도식 연결선을 곡선(dagre)에서 직각 배치(ELK, 선 모양 linear, 배치 NETWORK_SIMPLEX)로 바꿨다. assets/web/elk-adjust.ts가 배치 뒤 마주 보는 두 도형 사이 선을 꺾임 없이 펴고, 마름모는 꼭짓점에서만 선이 나고 들게 하고, 끝 쪽 짧은 계단을 없앤다. ER · 상태도는 그대로 dagre.
- 같은 두 도형 사이 글자 달린 선 셋(예: 폼 ↔ 목록 화면 사이 검사 통과 · 취소 버튼 · 글쓰기 버튼)의 글자가 겹치고 선이 글자를 지나간 버그가 있었다. 선을 펼 때 글자 두께만큼 띄우고, 겹친 구간에 다 안 들어가면 그 쌍은 펴지 않고 ELK의 글자 자리를 따른다(사용자가 꺾어서 글자 자리 확보를 고름).
- 그림 파일 렌더러는 웹 코드를 JS로 옮겨 쓰던 runtime.js를 버리고, assets/web/의 같은 TS 파일을 esbuild로 묶어 쓴다. 웹 화면과 그림 파일이 어긋나지 않게 하려는 것이다.

## 2026-10-10 ER 관계선 글자 없앰

- 테이블 10개 ERD를 그리니 관계선 글자(팔린다 · 묶는다 등)가 까마귀발 기호와 겹치고 상자에 가려졌다.
- 사용자가 "선과 선 사이 글자는 지우자"고 정했다. layout.ts의 dropRelationLabels가 그리기 전에 ER 관계 줄 글자를 비운다.
- 글자 자리가 빠지면서 같은 10개 ERD가 세로로 뒤집히지 않고 가로 81.9%, 글자 11.5px로 들어갔다(전에는 세로, 7.5px).

## 2026-10-10 두 렌더러 비교와 합침

- meta-mermaid와 codelab-mermaid(리엑트강의)가 10-08 원본에서 갈라졌다. 같은 원본 4종(흐름도 갈래 · 반복, ERD 10개, 상태도, 긴 한 줄)을 두 엔진으로 그려 비교했다.
- ERD와 긴 한 줄은 meta가 나았다. 순환이 있는 흐름도는 ELK가 시작 도형을 잘못 골라(로그인 화면이 옆으로 밀림, 실패 시나리오가 오류 표시부터 시작) dagre가 나았다.
- 그래서 순환 있는 흐름 도식은 dagre 곡선, 없으면 ELK로 정했다(사용자가 엔진 판단을 맡김).
- 흐름 도식 줄이기 단계를 살렸다. layout-elk는 spacing.baseValue를 40으로 박아 둬서, 줄일 때 mergeEdges 자리에 표시를 실어 보내고 elk-adjust가 20으로 바꾼다. 성공 시나리오가 두 줄 대신 한 줄(12.2px)로 들어갔다.
- codelab의 세 노드 순환(일자 + 아래로 돌아가는 선)을 assets/web/layout.ts로 옮겼다. codelab은 runtime.js에만 있어 웹 화면과 그림 파일이 달랐다.
- 쓰기 규칙은 사용자가 나눌지 판단하기 어렵다고 해서, 한 장으로 재 보고 정하기로 했다. height > width, fontPx < 11, 겹침 중 하나면 나눈다. 재기용으로 render.mjs --format none(파일 없음)과 결과 width · height를 더했다.
- 두 스킬은 같은 엔진 · 같은 쓰기 규칙을 쓴다. codelab-mermaid에는 리엑트강의 원고 위치만 더한다.

## 검토에서 더한 것

- AI가 원고에 %%{init: {"theme":"dark"}}%%나 frontmatter config를 넣으면 모양이 바뀌던 문제가 있었다. mermaid secure 목록으로 테마 키를 잠그고, 그리기 전에 init 줄 · frontmatter 설정을 지운다(제목만 남김).
- 뒤 단계(간격 좁히기 · 흐름 해석 · 줄바꿈 · 세로)가 실패하면 그때까지 가장 좋은 그림을 쓴다. 첫 그리기 실패만 그리지 못함으로 본다.
- 줄바꿈 글을 다시 만들 때 mermaid 내부 표시(#quot; → ﬂ°quot¶ß), 빈 라벨, 백틱을 되돌린다. 연결선 글자(i &lt; 10)는 디코딩해서 보인다.
