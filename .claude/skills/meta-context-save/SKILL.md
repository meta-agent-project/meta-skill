# meta-context-save

/clear 하면 사라지는 대화 내용을 파일로 남긴다.
무엇을 남길지는 사용자가 정한다. 대화에서 후보를 찾아 보여주고 고르게 한다.
불러오기는 /meta-context-restore가 한다.

## 남기는 것과 남기지 않는 것

| 남긴다 | 남기지 않는다 |
|---|---|
| 대화에서 정한 결정과 그 이유 | git 이력, 바뀐 파일 목록, 브랜치 |
| 고른 시안이나 선택지, 버린 쪽과 이유 | 파일에 이미 저장된 내용 (경로만 적는다) |
| 승인했지만 아직 파일에 없는 초안 | 명령 출력, 테스트 로그 |
| 승인을 기다리는 초안. 전문 그대로 | 이미 끝나서 다시 볼 일 없는 시행착오 |
| 열린 질문, 사용자가 아직 답하지 않은 것 | |
| 사용자가 강조한 말. 원문 그대로 | |
| 다음에 바로 할 일 | |

마지막에 나눈 대화가 가장 중요하다. 후보는 최근 것부터 찾는다.

## 저장 위치

```
~/.claude/meta-context/<프로젝트>/<세션 ID>.md
```

- 프로젝트 폴더 이름은 지금 작업 폴더 경로에서 영문, 숫자 밖의 글자를 - 로 바꾸고, 경로 해시 6자리를 붙여 만든다. 한글 이름만 다른 폴더끼리 겹치지 않게 한다
- 파일 이름은 세션 ID다. 세션 ID는 환경변수 CLAUDE_CODE_SESSION_ID에서 읽는다
- 세션마다 파일이 따로라 두 세션이 동시에 저장해도 서로 덮어쓰지 않는다
- 같은 세션에서 다시 저장하면 그 세션 파일을 새 내용으로 바꾼다
- 저장소 밖이라 git에 올라가지 않는다

```bash
SLUG="$(pwd | sed 's/[^A-Za-z0-9]/-/g')-$(pwd | md5sum | cut -c1-6)"
DIR="$HOME/.claude/meta-context/$SLUG"
mkdir -p "$DIR"
FILE="$DIR/$CLAUDE_CODE_SESSION_ID.md"
```

CLAUDE_CODE_SESSION_ID가 비어 있으면 date +%Y%m%d-%H%M%S로 대신한다.

## 순서

1. 후보 찾기
   이 대화를 최근 것부터 거꾸로 읽고 위 남긴다 표에 맞는 것을 찾는다.
   후보마다 한 줄로 쓴다. 무엇인지와 언제 나왔는지(마지막 대화, 중간, 처음)를 붙인다.

2. 인터뷰
   후보 목록을 번호를 붙여 채팅창에 보여준다.
   AskUserQuestion으로 묻는다. 한 번에 하나씩, 최대 4번.
   - 무엇을 남길까: 후보를 묶음별로 고르게 한다. multiSelect. 추천은 마지막 대화와 승인 대기 초안이다
   - 초안은 전문을 남길까, 요약할까: 초안이 있을 때만 묻는다. 추천은 전문이다
   - 더 남길 것이 있나: 사용자가 직접 적게 한다

3. 쓰기
   아래 형식으로 쓴다. 고르지 않은 것은 쓰지 않는다.
   - 맨 위 두 줄은 내가 정한다. 묻지 않는다
   - 제목: 이 대화창이 무엇을 하던 곳인지 3~8단어로 쓴다. 인자로 제목을 받았으면 그것을 쓴다
   - 요약: 어디까지 했고 무엇이 남았는지 한 문장으로 쓴다
   - restore 목록에는 이 두 줄만 보인다. 여러 세션 중에서 이것만 보고 고를 수 있게 쓴다
   - 결정과 선택은 무엇을, 왜를 한 줄씩 쓴다
   - 전문으로 남기기로 한 초안은 고치지 않고 그대로 붙인다
   - 사용자의 말은 원문 그대로 인용한다
   - 파일에 이미 있는 것은 경로만 적는다

4. 알리기
   제목, 요약, 저장한 경로, 남긴 항목 수를 보여준다.
   이제 /clear 하고 /meta-context-restore로 불러오면 된다고 알린다. /clear는 사용자가 직접 한다.

## 파일 형식

```
# dom-lab 강의 예제 만들기와 meta 스킬 정리
요약: post-list 장까지 끝냈고 fetch-posts spec 승인을 기다린다

세션: 345961ea-7e18-41b4-b03f-683a9c2edc1a
저장: 2026-10-10 14:30
작업 폴더: C:/workspace/...
이어서 할 일: fetch-posts spec 승인 받기

## 마지막 대화
- 사용자가 물은 것과 내가 답한 것의 요지
- 아직 답을 기다리는 질문: ...

## 결정
- 테스트는 정확한 값보다 동작을 본다. 이유: 서버 데이터가 바뀌어도 무너지지 않게
- 시안 B를 골랐다. 버린 A는 화면 끝까지 가는 header였다

## 승인 대기 초안
(전문 그대로)

## 사용자가 한 말
- 선택지가 중요한게 아니라, 이것도 다음부터 이런문제가 안일어나는게 중요한거자나

## 파일에 있는 것
- .projectcode/chapters/post-list/spec.md
```

## 지키는 것

- 대화를 지어내지 않는다. 대화에 있던 것만 쓴다
- 비밀번호, 토큰 같은 비밀은 쓰지 않는다
- 다른 세션의 파일은 건드리지 않는다
- 불러온 파일을 옮기는 것은 /meta-context-restore가 한다
