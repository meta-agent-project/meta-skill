# meta-image

견본 두 장을 매번 실제 이미지로 첨부해 강의 · 책 그림의 화풍을 맞춘다.
그림 본체는 흑백으로 두고 색은 구조 구분에만 쓴다.
넓은 다색 면은 설명보다 눈에 띄기 때문이다.

## 이 폴더

| 파일 | 하는 일 |
|---|---|
| assets/structure.png | 첫 번째 견본. 흑백 그림에 색 테두리 · 이름표로 포함 관계를 보인다 |
| assets/assembly.png | 두 번째 견본. 검정 펜과 회색 명암, 가벼운 입체감으로 개념을 보인다 |
| references/style.md | 생성 요청에 넣는 화풍 지침 |

## 생성 순서

- references/style.md를 읽고 두 PNG를 순서대로 연다
- 원고에서 핵심 개념, 관계, 방향, 이름표를 추린다. 장 수와 장마다 부분 · 순서 · 생성 요청을 함께 정한다
- 견본의 카페 · 손 · 조립 소재와 배치는 복사하지 않는다. 장면과 구도는 내용에 맞게 고른다
- 이미지 생성 도구의 참고 이미지 입력에 두 PNG를 실제로 첨부한다. 파일 이름이나 화풍 설명으로 대신하지 않는다
- 내용 참고를 검색했으면 세 번째로 보낸다. 첫 두 장은 화풍, 세 번째는 내용 자료라고 밝힌다. 검색 그림의 화풍은 따르지 않는다
- 화풍 지침은 최종 생성 요청에도 넣는다. 사용자의 명시적 수정 요청이 화풍보다 먼저다
- 요청 작성 AI와 이미지 생성 AI를 나눠 쓰면 양쪽에 두 PNG를 보낸다

## 검수

- 결과 PNG를 저장하고 직접 열어 확인한다
- 통과 기준은 내용, 관계, 수치, 이름표 철자의 정확성과 겹침 · 잘림 없는 가독성이다
- 핵심 오류가 있으면 위치와 수정 방향을 요청에 더해 같은 두 견본으로 한 번만 다시 만든다
- 색 · 장식 · 여백 취향은 경고로 알리고 핵심 오류와 나눈다. 강조색 개수로 탈락시키지 않는다
- 마지막까지 못 통과하면 그대로 알린다
- 결과 PNG의 색 · 배경 · 비율을 후처리로 바꾸지 않는다

## 실행 결과 예시

- 실행 결과 그림도 같은 화풍의 생성형 예시로 만들고 "생성형 예시 · 실제 실행 안 함"을 표시한다
- 예제 코드, 설치, DB, 서버는 실행하지 않는다
- 도구 · 설정 화면은 비워 두고 실제 사진은 사용자가 넣는다

## 한계

이미지 생성 도구나 참고 이미지 첨부를 쓸 수 없으면 그 제한을 알린다.
이미 승인된 그림은 요청받은 범위만 바꾼다.
화풍을 바꾸면 references/style.md와 두 견본을 함께 맞춘다.
